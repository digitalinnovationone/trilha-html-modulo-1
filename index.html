Introdução ⮌

Na Computação ao longo dos anos, sugiram e surgem novos conceitos e paradigmas de desenvolvimento de software.

Um dos que se consolidou até hoje é o POO(Programação Orientada a Objetos).

Diferentemente do paradigma funcional, cujo este - utiliza-se de funções para realização de cálculos/tarefas exatas - a POO possibilita ao desenvolvedor maior autonomia e integridade nas suas decisões.

A POO nada mais é do que construir software baseado em entidades e objetos do mundo real.

A POO se utiliza de diagramas de classe para visualização da modelagem de dados do negócio.

Classes x Objetos ⮌

Uma classe é o molde daquela entidade real a qual se quer construir. Exemplo: em um sistema de vendas, existe o Vendedor, o Produto e a Venda

Ambos são as entidades de negócio do meu projeto, ou seja, as classes

Já os objetos, são as instâncias da classe. Exemplo: Vendedor vend = new Vendedor();

O vend é o meu objeto criado a partir da classe Vendedor.

Em suma, classes são as entidades da ''planta'' do meu projeto enquanto os objetos são de fato, os ''tijolos'' reais.'

POO - Vantagens
Modelagem do mundo real Reutilização de código Manutenção simplificada Demenda do mercado
A POO permite que você modele sistemas complexos de uma maneira que reflete estruturas do mundo real. Com a POO, você pode criar componentes reutilizáveis, economizando tempo e esforço no desenvolvimento. O código orientado a objetos é geralmente mais fácil de entender e manter, especialmente em projetos grandes. Muitas empresas usam linguagens e frameworks orientados a objetos, tornando a POO uma habilidade valiosa no mercado de trabalho.


POO - Desvantagens
Complexidade Curva de aprendizado Desempenho
Para projetos pequenos, a POO pode adicionar complexidade desnecessária. Pode ser mais difícil para iniciantes entenderem os conceitos da POO. Em alguns casos, programas orientados a objetos podem ser mais lentos que os equivalentes procedurais.

Modelo Entidade - Relacionamento(ER) ⮌

Ao desenvolver um produto de software, os analistas de negócio elaboram um diagrama de entidades e seus relacionamentos

Características

  • Entidades: classes
  • Atributos: características da Entidade
  • Relacionamentos: relação entre as entidades de um sistema
Entidade Atributo Relacionamento
Pessoa CPF, nome, idade 1 pessoa compra n motos

Modelo(ER) - Vantagens x Desvantagens

Vantagens
Simplicidade e Clareza Facilita a compreensão da estrutura do banco de dados
por partes interessadas, incluindo membros não técnicos da equipe, sem a necessidade de conhecimento técnico aprofundado
Comunicação eficaz Os Modelos ER servem como uma excelente ferramenta de comunicação entre projetistas, desenvolvedores e usuários finais de bancos de dados.
A natureza visual dos diagramas ER facilita a discussão e o feedback, garantindo que todas as partes tenham um entendimento comum da estrutura do banco de dados.
Integridade dos dados Ao definir claramente os relacionamentos e restrições entre as entidades de dados, os Modelos ER ajudam a manter a integridade dos dado
Adaptabilidade Os Modelos ER são adaptáveis ​​e podem ser facilmente modificados para refletir mudanças nos requisitos do sistema.
Essa flexibilidade é essencial em ambientes de negócios dinâmicos, onde os requisitos de dados podem evoluir ao longo do tempo.

Desvantagens
Complexidade em grandes sistemas Embora os Modelos ER sejam simples para sistemas menores, eles podem se tornar extremamente complexos à medida que o sistema cresce.
Grandes bancos de dados com inúmeras entidades e relacionamentos podem resultar em diagramas complexos e difíceis de ler e gerenciar.
Desenvolvimento demorado A criação de um Modelo ER pode ser demorada, especialmente para bancos de dados grandes e complexos.
O processo exige planejamento meticuloso e análise detalhada para garantir a precisão, o que pode atrasar o cronograma de desenvolvimento.
Limitado ao design lógico Os Modelos ER concentram-se principalmente no design lógico de um banco de dados e não abordam diretamente o design físico do banco de dados.
Etapas adicionais são necessárias para traduzir o Modelo ER em um esquema físico, o que pode introduzir potenciais discrepâncias se não for tratado com cuidado.

Como a Orientação a Objetos se relaciona com o Modelo(ER) ⮌

A Programação Orientada a Objetos (POO) e o Modelo Entidade-Relacionamento (ER) são abordagens complementares na modelagem de sistemas.

Enquanto o Modelo ER foca na representação das entidades, atributos e relacionamentos em um nível conceitual do banco de dados, a POO permite representar essas entidades como classes, com seus métodos e comportamentos.

Na prática, o diagrama ER pode servir como base para o design das classes em POO, ajudando a garantir que os dados e suas relações sejam corretamente representados no software.

Por exemplo, uma entidade "Pessoa" no diagrama ER geralmente se torna uma classe "Pessoa" na POO, com atributos como "nome" e "idade", e métodos relacionados às suas operações.
